---
name: continuity-resolution-procedure
description: Procedure to record unresolved continuity mismatches during commit and how to document them
uses: functions.append_event, functions.register_promise, functions.pay_off_promise, functions.read_index, functions.read, functions.write_skill
---

1. When an approved scene contains verifier-blocking continuity mismatches that cannot be resolved before commit, record each mismatch as an unresolved finding in continuity/unresolved/<scene>.json. Each finding must include: - field: the canonical fact (entity and attribute) that mismatches - prose_quote: verbatim quote from the scene that triggered the mismatch - contradicts: the earlier fact it contradicts (file and quote) - reason: a short explanation why the mismatch is unresolved (e.g., needs author clarification, or requires retcon decision) - options: possible resolutions (e.g., accept and supersede; retcon earlier fact; mark as ambiguous and leave unresolved) 2. Register a meta promise with id meta:verifier-audit-inclusion:<scene> describing that the scene will be committed with unresolved findings and quoting the audit file path. 3. Include the verifier audit file contents verbatim in commit metadata and point to continuity/unresolved/<scene>.json. 4. The commit metadata must include a brief human-readable note summarizing what remains wrong and why it was left unresolved. 5. Record the unresolved findings into continuity logs so future scenes or retcons reference them. 6. When a later scene or retcon resolves the findings, append a resolving phase in the relevant relations or retcon files noting the scene that made the decision and the reasoning.
